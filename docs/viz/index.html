Fiche 01 — Erreur de Généralisation

Biais, Variance & Complexité

GE = Biais² + Variance + σ²ε (bruit irréductible). Plus un modèle est complexe (flexible), plus son biais diminue — mais sa variance augmente. L'objectif n'est pas de minimiser l'un ou l'autre, mais leur somme.

Complexité du modèle Modèle constant
Constant Ridge (linéaire) RF / GB réglés Arbre profond non régularisé
Décomposition GE = Biais² + Variance + σ²ε
La cible de fléchettes
Biais faible · Variance faible 🎯 Toutes les fléchettes groupées au centre — modèle idéal
Biais faible · Variance élevée 🎯 Éparpillées AUTOUR du centre — 1 arbre CART profond : juste en moyenne, très instable
Biais élevé · Variance faible 🎯 Groupées MAIS décalées — Ridge : cohérent mais systématiquement à côté
Biais élevé · Variance élevée 🎯 Éparpillées ET décalées — pire des cas
Biais = "je me trompe toujours de la même façon" — Ridge suppose une relation droite alors que la vraie relation âge → résistance est une courbe logarithmique. Peu importe la quantité de données, Ridge ne pourra jamais "voir" la courbe.
Variance = "je donne des réponses très différentes selon les données d'entraînement" — un arbre CART profond change complètement de structure si on retire 50 observations, donnant des prédictions très différentes pour le même béton (ex: 42 MPa vs 31 MPa).
Ridge — Underfit
Biais élevé, variance faible. RMSE = 10.4 MPa. Ne capte pas log(age) ni la loi de Féret quadratique.
Random Forest — Bon équilibre
Bagging de 300 arbres → variance maîtrisée. RMSE = 4.9 MPa.
Gradient Boosting — Meilleur équilibre
Correction itérative du biais résiduel. RMSE = 4.2 MPa ⭐

Pourquoi 5-fold ? Notre dataset a n=1005 → règle : 200 ≤ n ≤ 100 000 → 5-fold ou 10-fold. Bon compromis biais / variance / temps de calcul.

Anti-Overtuning

Avec une simple CV, sélectionner le meilleur HP parmi 72 configs est du cherry-picking sur des évaluations bruitées → estimation optimistement biaisée. La nested CV sépare strictement le tuning de l'évaluation.

Sans nested CV : on sélectionne le min d'une distribution bruitée. Preuve — classifieur aléatoire (GE=50%) avec 100 configs tunées → score apparent ~38% par chance. Le biais croît avec le nombre de configs testées.
Avec nested CV : le TEST EXTERNE est isolé avant le tuning. Le score qu'on en obtient n'est pas biaisé par la sélection des HPs. C'est l'estimation honnête de la GE.
Fiche 08 — CART, Random Forest & Gradient Boosting

Arbres, Bagging & Boosting

CART découpe l'espace des features en rectangles par des splits axis-aligned. RF moyenne 300 arbres bootstrapés (bagging → réduit la variance). GB entraîne 300 arbres séquentiellement, chacun corrigeant les erreurs résiduelles du précédent (boosting → réduit le biais).

CART — Découpage récursif de l'espace (axis-aligned splits)
🌲 Random Forest — Bagging réduit la variance

300 arbres profonds, chacun entraîné sur un échantillon bootstrap différent. Chaque arbre overfit individuellement (variance élevée) — mais leur moyenne est stable.

Chaque point = la prédiction d'un arbre pour le même béton. La ligne pointillée = vraie résistance. Le losange = moyenne des 300 arbres → bien plus proche de la cible que chaque arbre pris seul.
⚡ Gradient Boosting — Correction séquentielle des résidus

"Équipe de relais" : l'arbre 1 fait une prédiction grossière, l'arbre 2 corrige son erreur (résidu), l'arbre 3 corrige le résidu restant, etc. learning_rate=0.2 pondère chaque correction.

Bagging (RF) : Bootstrap Aggregating — entraîne N modèles sur N échantillons bootstrap (tirage avec remise) du même dataset, puis moyenne les prédictions. Réduit la variance sans augmenter le biais.
Boosting (GB) : entraîne les modèles séquentiellement, chacun sur les résidus du précédent : résidu = y_vrai − prédiction(modèles précédents). Réduit le biais itérativement.
Intégrité des Données

Data Leakage & Pipeline sklearn

Sans Pipeline sklearn, le StandardScaler voit les données de test lors de son fit() — contamination silencieuse qui gonfle artificiellement les performances. Le Pipeline garantit l'isolation par construction.

❌ Sans Pipeline — Leakage
scaler = StandardScaler() X_scaled = scaler.fit_transform(X) # ↑ calcule μ, σ sur TOUT X # (train + test = 1005 obs) cross_val_score(Ridge(), X_scaled, y) # test set contaminé !
✅ Avec Pipeline — Zéro Leakage
pipe = Pipeline([ ('scaler', StandardScaler()), ('model', Ridge()) ]) cross_val_score(pipe, X, y) # .fit() sur train seulement ✅ # garanti par construction
Règle d'or : tout preprocessing qui "apprend" des statistiques (μ, σ, médiane, corrélations, composantes PCA...) doit être dans le Pipeline. Le préfixe model__ dans param_grid cible la bonne étape du Pipeline.

Fiche 10 — Interprétabilité

Prédiction vs Explication

Un modèle peut être très précis (bonne prédiction) sans qu'on comprenne pourquoi (mauvaise explication). Les méthodes d'interprétabilité cherchent à répondre à : "pourquoi le modèle prédit-il ÇA pour CETTE observation ?"

Prédiction (accuracy) : "Quelle est la résistance prédite pour ce béton ?" → GB répond avec RMSE = 4.2 MPa. C'est la performance brute, mesurée par nested CV.
Explication (interpretability) : "Pourquoi GB prédit-il 45 MPa pour CE béton précis ?" → feature importance globale (qui compte en moyenne ?) ou locale (qu'est-ce qui a poussé CETTE prédiction vers le haut ?).
Partial Dependence (illustratif) — Résistance prédite vs Âge du béton

Toutes les autres features fixées à leur médiane, on fait varier age de 1 à 365 jours et on observe la prédiction. C'est l'illustration directe du biais de Ridge vu en Fiche 01.

GB (courbe) capture la forme logarithmique réelle de l'hydratation : forte progression les premiers jours, puis plateau. Ridge (droite) ne peut tracer qu'une ligne — il sous-estime les bétons jeunes et surestime les bétons très âgés. C'est le biais structurel de Ridge, visible directement.
Limite Impurity Importance : favorise les features continues à haute cardinalité (cement: 102-540) vs features avec beaucoup de zéros (fly_ash ~55% à 0). Permutation Importance est plus robuste mais coûteuse (re-prédire en permutant chaque colonne).
Global vs Local : feature importance (GB) et coefficients (Ridge) sont des explications globales — valables "en moyenne" sur tout le dataset. Des méthodes comme SHAP donnent des explications locales, par observation — hors scope de ce projet mais bonne piste pour aller plus loin.
Fiche 09 — Model Card (Mitchell et al., 2019)

Model Card du Projet

Documentation standardisée du modèle final retenu (Gradient Boosting), suivant le framework Mitchell et al. — clique sur chaque section pour la déplier.

1. Model Details

Modèle : Gradient Boosting Regressor (sklearn), dans un Pipeline avec StandardScaler.

Hyperparamètres : learning_rate=0.2, max_depth=4, n_estimators=300, subsample=1.0 — sélectionnés par GridSearchCV (5-fold inner CV).

Auteurs : Tim & Arnaud — projet académique I2ML 2026.

2. Intended Use

Usage prévu : estimer la résistance à la compression (MPa) d'une formulation de béton à partir de sa composition et de son âge — outil pédagogique d'aide à la formulation.

Hors scope : usage en production / certification structurelle réelle — le modèle n'a pas été validé sur des données externes au dataset UCI.

3. Factors

Facteurs pertinents : les 8 features (cement, slag, fly_ash, water, superplasticizer, coarse_agg, fine_agg, age) couvrent des plages réalistes de formulations de béton classique.

Facteur dominant : age (35.1% importance GB) et cement (29.2%) — cohérent avec la physique de l'hydratation.

4. Metrics

Métrique principale : RMSE (MPa) — interprétable directement par un ingénieur.

Métrique complémentaire : R² — variance expliquée, pour comparer les modèles entre eux.

Pourquoi pas MAE : seulement 0.8% d'outliers sur la target (analyse IQR) — RMSE reste pertinent.

5. Evaluation Data

Nested CV : 5-fold outer (seed=0) pour l'estimation de la GE, jamais vue pendant le tuning interne (5-fold inner, seed=42).

Coût : 5 × 5 × 72 = 1 800 entraînements pour GB (+360 pour le refit final) sur les ~4 135 entraînements totaux du projet.

6. Training Data

Source : UCI Concrete Compressive Strength dataset.

Taille après nettoyage : 1 005 observations (−25 doublons sur 1 030 originales).

Preprocessing : StandardScaler (μ=0, σ=1), encapsulé dans le Pipeline pour zéro data leakage.

7. Quantitative Analyses

Ridge (baseline) : RMSE = 10.385 ± 0.449 MPa, R² = 0.590

Random Forest : RMSE = 4.935 ± 0.318 MPa, R² = 0.907

Gradient Boosting ⭐ : RMSE = 4.208 ± 0.261 MPa, R² = 0.932

Le saut Ridge → GB (10.4 → 4.2 MPa) quantifie l'apport des relations non-linéaires (log(age), Féret quadratique).

8. Ethical Considerations

Aucune donnée personnelle — dataset purement physico-chimique. Risque principal : sur-confiance dans une prédiction hors de la plage d'entraînement (ex: formulations très exotiques) — le modèle extrapolerait silencieusement.

9. Caveats and Recommendations

Biais pessimiste : RMSE outer CV calculé sur des modèles entraînés à 80% — le modèle final (100% des données) est légèrement meilleur.

Recommandation : ne pas utiliser hors des plages de composition du dataset d'entraînement (ex: cement 102-540 kg/m³, age 1-365 jours). Réentraîner si de nouvelles formulations (béton fibré, etc.) sont introduites.
