# Objectif central

En ML, l’objectif ce n’est pas de faire un bon score sur les données qu’on a utilisées pour entraîner le modèle. Ce qu’on veut vraiment, c’est que le modèle performe bien sur des données futures qu’il n’a jamais vues. C’est ça, **l’erreur de généralisation**. Tout ce chapitre tourne autour d’une question : comment estimer de façon fiable cette capacité à généraliser, avec les données limitées qu’on a ?

---

## Slide 168 — Introduction à l’erreur de généralisation

**En ML on veut bien prédire sur des données futures inconnues, pas seulement sur le jeu d’entraînement.** Le problème c’est qu’un modèle a justement été optimisé pour minimiser l’erreur sur ce jeu d’entraînement — donc il est forcément biaisé dessus. **L’erreur qu’on va mesurer sur les données d’entraînement sera toujours trop optimiste par rapport à ce qui se passe en vrai.**

**Les concepts clés du thème :**
- Performance estimation
- Generalization error (GE)
- Différence modèle vs learner
- Inner loss vs outer loss

---

## Slide 169 — Performance Estimation

On entraîne via ERM sur $D_{train}$ :

$$
\hat{\theta} = \text{argmin}_\theta \frac{1}{n} \sum_i L(y_i, f(x_i \mid \theta))
$$

Le problème c’est que l’erreur sur les données d’entraînement est **optimistement biaisée** — le modèle a vu ces données, donc il s’y adapte. Ce qu’on veut vraiment mesurer, c’est la **generalization error** :

$$
GE(f) = \mathbb{E}_{(x,y) \sim P} [L(y, f(x))]
$$

La solution pratique : utiliser des **données test indépendantes**, jamais vues pendant l’entraînement. Ça simule ce qui se passe en production réelle.

---

## Slide 170 — GE pour un modèle fixé

Pour un modèle fixé $f$, la GE est l’espérance de la loss sur la vraie distribution :

$$
GE(f) = \mathbb{E}_{(x,y) \sim P_{xy}} [L(y, f(x))]
$$

En pratique, on ne connaît pas $P_{xy}$, donc on l’estime avec un dataset test indépendant $D_{test}$ :

$$
\hat{GE}(f) = \frac{1}{m} \sum_{i=1}^{m} L(y_i, f(x_i))
$$

<aside>
⚠️

Point crucial : réutiliser les données d’entraînement pour évaluer, c’est tricher. Le test set **doit être indépendant**.

</aside>

---

## Slide 171 — La test loss est une variable aléatoire

**Un point subtil qu’on oublie souvent** : même pour un modèle complètement fixé, la test loss est une **variable aléatoire**. **Pourquoi** ? Parce que le test set lui-même est un échantillon aléatoire tiré de la distribution. Si on tirait un autre test set, on obtiendrait une valeur différente.

La distribution de ces pertes $L(y, f(x))$ est souvent asymétrique avec de longues queues — **ce qui veut dire qu’une seule estimation de test loss est sujette à une variance non négligeable. C’est pour ça qu’on ne peut pas se fier à un seul split.**

> **Notes de cours** : **Dans l’exemple du prof, le modèle est entraîné sur 500 échantillons et testé sur 5000**. C’est inhabituel (généralement c’est l’inverse), mais ici c’était exprès pour avoir assez de points de test pour visualiser la distribution des pertes de façon quasi-continue. **En pratique on est plutôt sur des ratios 2/3 train, 1/3 test.**
>

## Slide 172 — Inner Loss vs Outer Loss

C’est un concept important et souvent mal compris. On a **deux fonctions de perte différentes** qui jouent des rôles différents :

**Inner loss** (perte interne) :
- Celle utilisée pour entraîner le modèle, optimisée via ERM
- Doit être différentiable, convexe, favorable à l’optimisation
- Exemple : log-loss pour la régression logistique

**Outer loss** (perte externe) :
- Celle utilisée pour évaluer la performance réelle du modèle
- Peut être n’importe quelle métrique qui reflète ce qu’on veut vraiment mesurer
- Exemple : 0-1 loss (taux d’erreur de classification)

<aside>
⚠️

Pourquoi séparer les deux ? Parce que la métrique qui nous intéresse vraiment est souvent impossible à optimiser directement. La 0-1 loss par exemple est une fonction en escalier, non différentiable — si on essaie de minimiser ça directement, c’est un problème NP-difficile, inutilisable en pratique. On utilise alors la log-loss comme surrogate pendant l’entraînement, puis on évalue avec le taux d’erreur réel.

</aside>

> **Notes de cours** : Le prof insiste là-dessus — parfois on utilise une inner loss différente juste parce que l’optimisation est plus rapide. Parfois c’est parce que la vraie métrique est littéralement impossible à optimiser par gradient. Les deux cas existent.
>

## Slide 173 — Set-Based Performance Metrics

**Une métrique de performance $\rho$** mesure la qualité globale sur un test set entier : $\rho(Y, F) \in \mathbb{R}$. Dans le cas le plus simple, c’est juste la moyenne d’une loss observation par observation. Mais certaines métriques importantes ne se décomposent pas comme ça.

**L’AUC, le F1-score ou les métriques de survie (où on mesure des durées sans toujours avoir l’observation finale) nécessitent l’ensemble complet des prédictions pour être calculées** — impossible de les calculer sur un seul échantillon isolé. Dans ce cas la notation utilisée est $\rho(Y, F)$ où $F$ est l’ensemble de toutes les prédictions sur le test set.

Quand la métrique se réduit à une loss moyenne, ça rentre naturellement dans ce cadre. Mais c’est bon de savoir que ça ne se limite pas à ça.

<aside>
⚠️

- **Métrique simple** (ex: taux d'erreur) → calcul point par point puis moyenne → pas besoin de tous les points en même temps
- **Métrique complexe** (ex: AUC, F1) → besoin de tous les points ensemble pour être calculée
</aside>

## Slide 174 — GE du modèle vs GE du Learner ⚡ IMPORTANT

C’est ici que ça devient un peu **schizophrénique**.

En pratique, on a souvent **un seul dataset**. Et on voudrait à la fois utiliser toutes les données pour entraîner le meilleur modèle possible, ET garder des données vierges pour évaluer honnêtement ce modèle. On ne peut pas faire les deux en même temps.

**La solution conceptuelle : au lieu d’évaluer un modèle spécifique, on évalue le learner $\mathcal{I}$ — c’est-à-dire l’algorithme d’apprentissage avec ses hyperparamètres, pour une certaine taille de données.**

$$
GE(\mathcal{I}, \lambda, n_{train}, \rho) = \mathbb{E}\left[ \rho(Y_{test}, \hat{f}(X_{test})) \right]
$$

Le processus pratique :
1. Faire plusieurs apprentissages sur des sous-ensembles des données
2. Tester sur les données restantes à chaque fois
3. Faire la moyenne des erreurs obtenues — ça permet de choisir le bon modèle / les bons hyperparamètres
4. Une fois le meilleur candidat identifié, **réentraîner sur toutes les données disponibles**
5. Espérer que l’erreur mesurée pendant les étapes intermédiaires est représentative de la vraie performance en production

Les modèles appris pendant cette procédure sont des **modèles intermédiaires** — pas le modèle final. Ils servent uniquement à estimer la performance du learner.

<aside>
⚠️

**Notes de cours** : Ce qu’on évalue vraiment, c’est pas l’erreur d’un modèle particulier. C’est l’erreur d’un algorithme d’apprentissage avec certains paramètres et une certaine taille de données. “Si je fais une régression polynomiale de degré 3 avec 1000 échantillons, j’aurai telle erreur en moyenne.” C’est ça la GE du learner.

- **GE modèle** : erreur d'un modèle précis sur un test set précis
- **GE learner** : erreur moyenne d'un algorithme avec ses hyperparamètres, estimée via cross-validation sur plusieurs tours
</aside>

---

## Slide 175 — Resampling & Biais Pessimiste

Ce processus itératif s’appelle le **resampling** — **on rééchantillonne plusieurs fois les données pour stabiliser l’estimation de l’erreur.**

**Biais pessimiste** : puisque les modèles intermédiaires sont entraînés sur $n_{train} < n$ données, ils sont forcément un peu moins bons que le modèle final qui utilisera toutes les données. L’estimateur de la GE va donc légèrement **sous-estimer** la vraie performance du modèle final. C’est l’inverse du problème avec la training error (qui sur-estime) — ici on sous-estime.

Plus l’ensemble d’entraînement est petit par rapport au dataset complet, plus ce biais pessimiste est fort.

<aside>
⚠️

Ici c’est assez simple en fait, le resampling est le nom du mécanisme qu’on a vu juste avant, en fait le resampling permet d’obtenir la GE du learner, en fait étant donné qu’on utilise des échantillons plus petits en cross validation que le dataset complet forcément le GE du learner sera un peu plus petite que la performance réelle du modèle 

La GE du learner c'est la **moyenne des GE intermédiaires**. Et ces GE intermédiaires ont été calculées sur des sous-ensembles plus petits → donc légèrement pessimistes → donc la moyenne est aussi légèrement pessimiste.

Le modèle final lui est entraîné sur tout le dataset → il sera un peu meilleur que ce que la GE du learner prédit !

</aside>

## Slide 177 — Métriques pour la Régression

Pour la régression ($Y \in \mathbb{R}$), voici les métriques classiques à connaître :

**MSE — Mean Squared Error** :

$$
MSE = \frac{1}{m} \sum_{i=1}^{m} (y_i - \hat{y}_i)^2
$$

- Pénalise fortement les grandes erreurs (au carré)
- Sensible aux outliers
- Différentiable, convexe, favorable à l’optimisation

**RMSE — Root Mean Squared Error** :

$$
RMSE = \sqrt{MSE}
$$

- Même chose que MSE mais dans la même unité que $Y$
- Plus facile à interpréter
- Propriétés statistiques intéressantes sur la distribution des résidus

**MAE — Mean Absolute Error** :

$$
MAE = \frac{1}{m} \sum_{i=1}^{m} |y_i - \hat{y}_i|
$$

- Moins sensible aux outliers que MSE
- Non différentiable en 0
- Variante : utiliser la médiane au lieu de la moyenne, encore plus robuste

**MAPE — Mean Absolute Percentage Error** :

$$
MAPE = \frac{1}{m} \sum_{i=1}^{m} \left|\frac{y_i - \hat{y}_i}{y_i}\right|
$$

- Erreur exprimée en pourcentage de la valeur réelle → sans unité, interprétable directement
- Utile quand l’erreur doit être proportionnelle à la valeur prédite (prédire 1 au lieu de 3 c’est plus grave que prédire 99 au lieu de 101)
- **Problème** : indéfini si $y_i = 0$. Pas utilisable dans ce cas.

<aside>
⚠️

**Notes de cours** : Le prof dit “si vous êtes à hauteur distance ici ou là, vous renvoyez la même erreur absolue — c’est juste la distance par rapport à la prédiction.” La MAPE corrige ça en mettant l’erreur en perspective par rapport à la vraie valeur. Les variantes SMAPE et MASE existent pour contourner le problème du zéro.

</aside>

## Slide 180 — R² et ses limites

$$
R^2 = 1 - \frac{SSE_{modèle}}{SSE_{intercept}} = 1 - \frac{\sum(y_i - \hat{y}_i)^2}{\sum(y_i - \bar{y})^2}
$$

<aside>
⚠️

**L’idée : on compare l’erreur de notre modèle à l’erreur d’un modèle trivial qui prédit toujours la moyenne $\bar{y}$. Le SSE intercept mesure la variance intrinsèque des données. Si $R^2 = 0.9$, ça veut dire qu’on fait 10 fois mieux que prédire la moyenne — le modèle explique 90% de la variance.**

</aside>

Cas particuliers :
- $R^2 = 1$ : prédiction parfaite
- $R^2 = 0$ : pas mieux que prédire la moyenne
- $R^2 < 0$ : **pire** que prédire la moyenne (possible hors du jeu d’entraînement)
- Sur les données d’entraînement pour un modèle linéaire, $R^2 \in [0,1]$ par construction

<aside>
⚠️

**Limite importante : un $R^2$ plus élevé n’indique pas forcément un meilleur modèle. Exemple concret du prof : on apprend un modèle linéaire sur des données entre 0 et 0.5. On obtient $R^2 = 0.74$. On rajoute des données entre 0.5 et 1.0 — le MSE reste identique (le modèle n’a pas changé), mais $R^2$ augmente à 0.9. Pourquoi ? Parce qu’avec plus de données, la moyenne $\bar{y}$ bouge, ce qui change le SSE intercept. Le $R^2$ a augmenté sans que le modèle soit meilleur.**

</aside>

<aside>
⚠️

NB : sur l’image, on a moins de données et donc la moyenne est plus basse au niveau de 0.3 disons, alors qu’après on ajoute des données et donc la moyenne change de place, on a donc augmenté le R2 mais sans que le modèle soit meilleur, donc un R2 plus élevé ne signifie pas un meilleur modèle

</aside>

![image.png](image.png)

**Avantage** de $R^2$ par rapport à MSE : il est **invariant au changement d’unité ou d’échelle de $Y$**. Si vous doublez toutes les valeurs de sortie, le $R^2$ ne change pas. Le MSE lui, dépend de l’échelle — ce qui rend les comparaisons entre deux études difficiles si les unités sont différentes.

**R² généralisé** : en ML, on peut comparer n’importe quel modèle complexe à une baseline simple :

$$
R^2_{gen} = 1 - \frac{Loss_{complexe}}{Loss_{baseline}}
$$

Peut devenir négatif si le modèle complexe est moins bon que la baseline.

<aside>
⚠️

**Notes de cours** : Le seuil d’un “bon” $R^2$ dépend totalement du domaine. En physique, $R^2 = 0.9$ peut être considéré comme faible. En sciences sociales, $R^2 = 0.3$ peut être acceptable. Avec 10 échantillons, on peut pas faire des miracles.

</aside>

## Slide 184 — Corrélation de Spearman

**Parfois on s’intéresse pas tant aux valeurs prédites qu’au classement des observations. Par exemple dans un concours, ce qui compte c’est de savoir qui est classé devant qui, pas les notes exactes.**

La corrélation de Spearman mesure ça : elle regarde si l’ordre relatif des prédictions est cohérent avec l’ordre réel.

$$
\rho_s = \text{Corr}(\text{rank}(Y), \text{rank}(\hat{Y})) \in [-1, 1]
$$

On remplace chaque valeur par son rang (si j’ai 30, 50, 42 → je remplace par 1, 3, 2) et on calcule la corrélation entre ces rangs.

- $\rho_s = 1$ : relation monotone croissante parfaite — le modèle classe les observations dans le même ordre que la réalité
- $\rho_s = -1$ : relation monotone décroissante parfaite — ordre inversé
- $\rho_s = 0$ : totalement aléatoire, aucun rapport entre les ordres

Avantages : robuste aux outliers, invariant à toute transformation monotone des valeurs. Utile pour le ranking, la recommandation, la finance.

### Example

| Étudiant | Vraie note | Prédiction |
| --- | --- | --- |
| A | 30 | 25 |
| B | 50 | 55 |
| C | 42 | 40 |

On remplace par les **rangs** (1 = plus petit) :

| Étudiant | Rang réel | Rang prédit |
| --- | --- | --- |
| A | 1 | 1 |
| B | 3 | 3 |
| C | 2 | 2 |

---

Les rangs sont **identiques** → Spearman = 1 ! Le modèle prédit pas les bonnes notes exactes mais il classe les étudiants dans le **bon ordre**.

### Example

La courbe représente l’intervalle de confiance, à gauche corrélation parfaite parce que les points augmentent quand la courbe monte et à droite c’est l’inverse ⇒ aucune corrélation de spearman

## Slide 185 — Training Error : définition et pièges

<aside>
⚠️

L’**erreur d’entraînement** (apparent error, resubstitution error) c’est simplement la GE mesurée en utilisant les données d’entraînement comme données de test — on “refourgue” les mêmes données à l’algorithme une deuxième fois.

</aside>

Elle est structurellement **biaisée de manière optimiste** : le modèle a été construit pour minimiser exactement ça.

**Exemple avec k-NN** : k-NN retient tous les points d’entraînement en mémoire. Pour prédire un nouveau point, on trouve ses $k$ plus proches voisins et on fait la moyenne de leurs valeurs.

- Si $k$ est grand : on lisse beaucoup, training error un peu plus élevée mais meilleure généralisation
- Si on descend jusqu’à **$k = 1$** : le plus proche voisin d’un point d’entraînement, c’est lui-même. Le modèle lui ressort exactement sa propre étiquette → training error = **0**. Mais sur de nouvelles données ? Catastrophique.

Autre exemple : **régression polynomiale**. Plus on augmente le degré $d$, plus on passe près des points d’entraînement, plus la training error baisse. À degré 9, MSE = 0.001. Mais sur le test set, le degré 3 performe bien mieux. La training error minimise toujours avec la complexité — c’est pour ça qu’on ne peut pas s’y fier seule.

<aside>
⚠️

**Notes de cours** : Il existe des cas où la training error peut tomber à zéro même sans k-NN : la mémorisation (on retient les échantillons vus et on les ressort directement), ou les modèles d’interpolation (courbe piecewise qui passe exactement par chaque point). Dans ces cas, la training error est nécessairement zéro si l’apprentissage a été fait correctement — c’est une métrique à laquelle on ne peut **absolument pas** se fier.

</aside>

Mesures classiques GOF (goodness-of-fit) en stats : $R^2$, AIC, BIC, déviance — toutes basées sur la training error.

- **AIC** (Akaike Information Criterion) : $MSE + 2k$ où $k$ = nombre de features — pénalise la complexité
- **BIC** (Bayesian Information Criterion) : $MSE + k \cdot \ln(n)$ — pénalise encore plus fortement la complexité selon la taille de l’échantillon
- L’idée dans les deux cas : favoriser des modèles plus simples, pas uniquement le fit. Si deux modèles ont le même MSE, on préfère celui avec moins de features.

Ces mesures peuvent fonctionner si le modèle a une capacité limitée et si les hypothèses sont respectées. Mais en ML moderne avec des modèles très flexibles : **tester sur des nouvelles données non vues est toujours une bonne idée**.

## Slide 193 — Test Error

L’erreur de test c’est simplement la métrique mesurée sur un ensemble de données qu’on a mis de côté et que le modèle n’a jamais vues :

$$
\rho(Y_{test}, F_{test})
$$

Avantages par rapport à la training error :
- Données indépendantes
- Simule l’usage réel du modèle
- Moins biaisée optimistement

Mais elle a toujours une **variance** associée à l’estimation — elle dépend du split choisi.

---

## Slide 194-196 — Hold-Out

La méthode de base : on divise le dataset en deux parties, typiquement **2/3 train, 1/3 test**. On entraîne sur $D_{train}$, on prédit sur $D_{test}$, on calcule l’erreur.

Sur l’exemple de régression polynomiale avec hold-out :
- $d = 1$ → $MSE_{test} = 0.038$ → underfitting
- $d = 3$ → $MSE_{test} = 0.002$ → bon compromis
- $d = 9$ → $MSE_{test} = 0.046$ → overfitting

Observation fondamentale : la training error baisse toujours quand la complexité augmente. La test error suit une **courbe en U** — elle diminue d’abord puis remonte.

**Dilemme du hold-out** :
- Plus on alloue de données au train → meilleur modèle mais estimation de l’erreur plus instable (petit test set)
- Plus on alloue au test → estimation stable mais modèle sous-optimal (petit train set)

<aside>
⚠️

**Notes de cours** : Des expériences empiriques (sur des données de spirale, CART tree, 500 éléments, 50 répétitions par split) montrent que le ratio optimal qui minimise le MSE de l’estimateur hold-out est autour de **2/3 train**. C’est une règle empirique qui marche souvent bien dans plein de domaines, mais c’est pas une loi universelle. Si on a vraiment énormément de données, on peut se permettre du 90/10.

</aside>

## Slide 197-203 — Bias-Variance de l’estimateur hold-out

Trois facteurs influencent la qualité de l’estimation de l’erreur :

**Taille du training set** :
- Plus il est grand → modèle mieux estimé → biais de l’estimateur plus faible
- Plus il est petit → modèle sous-optimal → estimateur pessimiste

**Taille du test set** :
- Plus il est grand → variance de l’estimation faible → résultat stable
- Plus il est petit → grande variance → estimations instables selon le split

**Complexité du modèle** :
- Plus le modèle est complexe → prédictions instables → variance élevée

**Quand les données sont limitées, on est dans un dilemme : augmenter le train diminue le biais mais augmente la variance de l’estimation. Le ratio 2/3 est un compromis empiriquement raisonnable.**

Sur un test set dédié et indépendant, l’estimateur est **non biaisé** avec une variance qui décroît en $1/m$. Par le CLT, pour des test sets suffisamment grands, l’estimateur converge vers une loi normale → intervalles de confiance possibles.

## Slide 208-211 — Underfitting et Overfitting

**Underfitting : modèle trop simple, il ne capture pas la complexité des données.**
- Training error élevée ET test error élevée
- Biais élevé, variance faible
- Formellement : $UF(\hat{f}, L) = GE(\hat{f}, L) - GE(f^*, L)$ — distance au meilleur modèle possible
- Difficile à détecter car on ne connaît pas l’erreur de Bayes (l’erreur minimale théorique)

**Overfitting : modèle trop complexe, il apprend le bruit en plus du signal.**
- Training error très faible, test error élevée
- Biais faible, variance élevée
- Formellement : $OF(\hat{f}, L) = GE(\hat{f}, L) - R_{emp}(\hat{f}, L)$ — écart entre performance réelle et apparente
- Plus facile à détecter : on voit la divergence entre train error et test error

**On peut avoir les deux en même temps (modèle qui fait de l’overfitting sur certaines zones et de l’underfitting sur d’autres). Dans ce cas, on considère que c’est de l’overfitting qui est prioritaire.**

| Phénomène | Biais | Variance | Train Error | Test Error |
| --- | --- | --- | --- | --- |
| Underfitting | Élevé | Faible | Élevée | Élevée |
| Sweet spot | Équilibré | Équilibrée | Moyenne | Basse |
| Overfitting | Faible | Élevée | Très basse | Élevée |

**Facteurs qui provoquent l’overfitting** :
- Complexité de l’espace d’hypothèses $\mathcal{H}$ (10M de paramètres vs 5)
- Peu de données d’entraînement (le modèle mémorise le bruit)
- Haute dimensionnalité des features (plus de features = plus de risque de trouver des patterns artificiels)
- Bruit irréductible dans les données

**Stratégies pour l’éviter** :
- Plus de données (data augmentation si impossible d’en collecter plus — flip d’images, changements de résolution, etc.)
- Restreindre $\mathcal{H}$ (modèle plus simple)
- Régularisation
- Early stopping (arrêter l’entraînement quand la test error commence à remonter)
- Principe d’Occam : si deux modèles ont des performances similaires, prendre le plus simple

<aside>
⚠️

**Notes de cours** : Le prof insiste — “le plus simple, mais le plus simple qui marche.” Et une contrainte souvent oubliée : si vous avez 30 échantillons, un réseau de neurones profond ne servira à rien. Le choix de complexité doit être proportionnel à la quantité de données disponibles.

Moins on a de données + il y a du risque d’overfitting car le modèle peut apprendre parfaitement les quelques points erreur = 0

## Slide 213 —  COMPLEXITY VS GE

<aside>
⚠️

## Slide 215-218 — Resampling & Cross-Validation

Le hold-out simple est instable : il dépend trop du split choisi. La solution : **répéter** le processus plusieurs fois et faire la moyenne des erreurs.

**Principe général** : on définit une collection de splits $\mathcal{J} = \{(J_{train,b}, J_{test,b})\}_{b=1}^B$ et on estime :

$$
\hat{GE} = \text{agr}(\rho_1, \rho_2, \dots, \rho_B)
$$

où `agr` est souvent la moyenne. Ça réduit la variance sans changer le biais (pour un même ratio train/test).

<aside>
⚠️

**Donc le GE du learner obtenu par cross validation, chaque ‘tour’ donne une GE intermédiaire (GE du modèle) sur un set précis, ensuite le GE du learner est la moyenne de tous ces GE intermédiaire donc GE = 1/m (ge1, ge2, ge3, gem…)**

***NB*** : on peut aussi obtenir la GE du learner en faisant : **hold-out répété mais c’est plus utilisée la CV**

</aside>

**K-Fold Cross-Validation** :
- On divise les données en $K$ blocs de taille égale
- À chaque itération : $K-1$ blocs → train, 1 bloc → test
- On répète $K$ fois — chaque observation est testée exactement une fois
- Fraction d’entraînement : $(K-1)/K$ → avec 10-fold : 90% en train
- Erreur finale :

$$
CV_{error} = \frac{1}{K} \sum_{k=1}^{K} E_k
$$

Valeurs standard en pratique : **5-fold ou 10-fold**. Pour des petits datasets ($n < 200$) : LOO ou CV répétée.

## Slide 219 — Stratified Cross-Validation

<aside>
⚠️

**Si les classes sont déséquilibrées** (ex : 10% de survivants dans le Titanic), **un découpage aléatoire peut mettre tous les survivants dans le même fold** — et donc entraîner un modèle sur des données sans aucun positif.

</aside>

<aside>
⚠️

**La CV stratifiée maintient les proportions de classes dans chaque fold : on coupe chaque classe séparément en $K$ blocs, puis on regroupe. Chaque fold a la même répartition que le dataset complet.**

</aside>

## Slide 220 — Leave-One-Out (LOO)

Cas extrême de la CV : $K = n$. À chaque itération, on entraîne sur $n-1$ points et on teste sur 1.

- Biais quasi nul (on entraîne presque sur toutes les données)
- Grande variance (un seul point de test par itération)
- Coût computationnel élevé : si $n = 1000$, on entraîne 1000 modèles sur 999 points chacun

En pratique, LOO est rarement utilisé sauf si on a vraiment très peu de données. Le 5-fold ou 10-fold offre un meilleur compromis.

---

## Slide 221 — Subsampling (Monte Carlo CV)

On répète un hold-out aléatoire $B$ fois avec un ratio train fixé (typiquement 80% ou 90%), puis on fait la moyenne.

- Même biais pessimiste que le hold-out pour un même ratio
- Variance beaucoup plus faible grâce à l’averaging
- Permet d’utiliser des ratios train plus élevés (~80%) sans variance explosive
- Plus de répétitions → variance plus faible (comme faire la moyenne de tirages aléatoires)

**Comment savoir quand arrêter ?** Si on répète 10 fois et qu’on obtient chaque fois plus ou moins la même erreur, c’est stable. Si les résultats varient fortement d’une répétition à l’autre, il faut continuer.

---

## Slide 222 — Bootstrap

Le bootstrap tire $B$ datasets d’entraînement **avec remise** de taille $n$. Les points non sélectionnés (out-of-bag, OOB) servent de test.

- En tirant avec remise, un bootstrap sample contient en moyenne **63.2%** de points uniques (car $(1-1/n)^n \to 1-1/e \approx 0.368$ est la proba de ne pas être sélectionné)
- Environ **36.8%** de duplicats dans chaque training set

Le prof le mentionne mais n’est pas fan de cette méthode. **Le problème des duplicats** : les échantillons dans le training set ne sont plus indépendants (certains sont littéralement identiques). Ça peut causer des problèmes selon le learner. Des variantes comme **Bootstrap 632** et **Bootstrap 632+** tentent de corriger ces biais, mais c’est compliqué. Plutôt réservé aux datasets vraiment très petits.

---

## Slide 223 — Leave-One-Object-Out

Cas particulier important quand les données ne sont pas i.i.d. Par exemple :
- Plusieurs prises de sang d’un même patient
- Plusieurs images d’une même personne

Si ce patient se retrouve à la fois dans le train et dans le test → fuite d’information → estimation biaisée optimistement. Le modèle a “vu” ce patient avant.

Solution : **grouper par objet**. Tous les échantillons d’un même patient sont soit en train, soit en test — jamais les deux. On fait ensuite une CV en laissant un patient complet de côté à chaque itération.

<aside>
⚠️

C'est un cas extrême de la CV où K = n (nombre de données) !

À chaque tour, on laisse **un seul point** comme test et on entraîne sur tout le reste.

Exemple avec 100 données :

- Tour 1 : entraîne sur 99 points, teste sur le point 1
- Tour 2 : entraîne sur 99 points, teste sur le point 2
- ...
- Tour 100 : entraîne sur 99 points, teste sur le point 100

**Avantage** : on utilise presque toutes les données pour entraîner à chaque tour.
**Inconvénient** : très lent ! Si t'as 10 000 données → 10 000 tours !

</aside>

> **Notes de cours** : Résultat théorique important de Bengio (2004) — il n’existe **pas d’estimateur non biaisé** de la variance de $\hat{GE}_{CV}$. La variance empirique des $K$ folds sous-estime systématiquement la vraie variance, parce que les folds partagent des données d’entraînement (corrélation). Ne pas appliquer naïvement un t-test sur des résultats de folds CV — les hypothèses d’indépendance sont violées.
> 

| Méthode | Biais | Variance | Usage recommandé |
| --- | --- | --- | --- |
| Hold-out | Pessimiste | Élevée | Grands datasets, vite |
| K-fold CV | Pessimiste léger | Moyenne | Standard |
| LOO | Très faible | Élevée | Petits datasets |
| Subsampling | Pessimiste léger | Faible | Flexible |
| Bootstrap | Faible | Moyenne | Très petits datasets |

## Slides 225-226 — Analyse biais-variance : holdout vs subsampling

On reprend l’expérience classique sur les données en spirale. On compare deux approches :
- **Hold-out** : un seul split train/test, une seule estimation
- **Subsampling** : 50 répétitions du hold-out avec le même ratio $s$, puis moyenne des erreurs

On fait varier le ratio $s \in \{0.05, 0.10, \dots, 0.95\}$ avec $|D_{train}| = s \times 500$, et on répète 50 fois pour chaque valeur de $s$.

Ce qu’on observe sur le graphe (en MCE) :
- Les deux estimateurs sont comparés à la vraie MCE (ligne noire)
- Pour un même $s$, le subsampling a **le même biais pessimiste** que le hold-out
- Mais la **variance est beaucoup plus faible** pour le subsampling

![image.png](image%208.png)

**La logique est simple** : quand on fait 50 fois l’opération et qu’on fait la moyenne, on lisse les fluctuations aléatoires dues au tirage du split. Le biais ne change pas parce qu’on entraîne toujours sur $n_{train} < n$ données — c’est structurel. Mais la variance, elle, diminue linéairement avec le nombre de répétitions.

<aside>
⚠️

**Notes de cours** : Le prof insiste — “**la variance décroît linéairement avec le nombre d’expériences**”. Donc plus on répète, plus l’estimation est stable. Mais attention, ça ne veut pas dire qu’on peut répéter à l’infini et tout résoudre — on va voir pourquoi ça a des limites.

</aside>

---

## Slide 227 — MSE de l’estimateur GE : subsampling strictement meilleur

Sur ce graphe, on trace le **MSE de l’estimateur $\widehat{GE}$** (c’est-à-dire l’écart quadratique entre l’estimateur et la vraie GE) en fonction du ratio de split $s$, pour le hold-out et le subsampling.

Résultats clés :
- Le MSE du subsampling est **strictement inférieur** à celui du hold-out pour tous les splits — **le subsampling gagne à tous les coups**
- Pour le **hold-out**, le minimum se trouve autour de $s \approx 2/3$ (ce qu’on avait vu la dernière fois)
- Pour le **subsampling**, le minimum se déplace vers $s \approx 0.8$ — **on peut se permettre un train set plus grand** parce que la variance réduite compense

**Pourquoi ça remonte** au-delà de $s = 0.8$ ? Parce qu’au-delà de ce seuil, les training sets des différentes répétitions se **recouvrent de plus en plus**. Les splits ne sont plus du tout indépendants, les échantillons de test deviennent minuscules, et on n’arrive plus à réduire la variance suffisamment pour compenser le biais. **C’est la limite du subsampling.**

<aside>
⚠️

**En fait ici, la réelle limite du subsampling c’est la taille du dataset en fonction du nombre d’itération, par exemple si t’as un dataset de 100 données et que tu fais un s = 0.95 donc test train de 95 données et 5 pour le test et que tu fais 50 entrainements, en fait il va prendre presque toujours les même données… pour entraîner et donc les itérations n’apportent plus rien**

</aside>

## Slide 228 — Dedicated test set : analyse formelle

Dans le cas idéal où on a un test set **fixe et indépendant**, les propriétés de l’estimateur sont très propres :

$$
\widehat{GE}(\hat{f}) = \frac{1}{m} \sum_{(\mathbf{x},y) \in D_{test}} L(y, \hat{f}(\mathbf{x}))
$$

Ici, les $(x, y)$ sont des variables aléatoires i.i.d. tirées de la vraie distribution. C’est donc une moyenne de $m$ variables indépendantes. On peut directement calculer :

$$
\mathbb{E}[\widehat{GE}(\hat{f})] = GE(\hat{f}) \quad \Rightarrow \text{ estimateur non biaisé}
$$

$$
\mathbb{V}[\widehat{GE}(\hat{f})] = \frac{1}{m} \mathbb{V}[L(y, \hat{f}(\mathbf{x}))] \quad \Rightarrow \text{ variance décroît linéairement avec } m
$$

Et par le théorème central limite (CLT), pour $m$ suffisamment grand, $\widehat{GE}$ suit approximativement une loi normale — ce qui permet de faire des tests d’hypothèses et des intervalles de confiance.

<aside>
⚠️

**Notes de cours** : La Gaussienne peut moins bien marcher pour la 0-1 loss quand l’erreur est proche de 0 (distribution très asymétrique). Dans ce cas on peut utiliser une approximation binomiale à la place.

</aside>

## Slide 229-230 — Biais pessimiste en resampling : formalisation

En resampling (CV ou subsampling), on n’a pas un modèle fixé $\hat{f}$ — on réentraîne à chaque split. L’estimateur s’écrit :

$$
\widehat{GE}(\mathcal{I}, \mathcal{J}, \rho, \lambda) = \text{agr}\left(\rho(\mathbf{y}_{J_{test,1}}, F_{J_{test,1}, \mathcal{I}(D_{train,1}, \lambda)}), \dots\right)
$$

Si agr = moyenne et $\rho$ est basé sur une loss, alors :

$$
\mathbb{E}[\widehat{GE}(\mathcal{I}, \mathcal{J}, \rho, \lambda)] \approx \mathbb{E}\left[\rho\left(\mathbf{y}_{J_{test}}, F_{J_{test}, \mathcal{I}(D_{train}, \lambda)}\right)\right] = GE(\mathcal{I}, n_{train})
$$

Ce qu’on estime en réalité c’est $GE(\mathcal{I}, n_{train})$, pas $GE(\mathcal{I}, n)$. Or entraîner sur $n_{train} < n$ données donne un modèle moins bon → l’estimateur **sous-estime la performance du modèle final**. C’est le biais pessimiste. Et plus $n_{train}$ est petit par rapport à $n$, plus ce biais est fort.

---

## Slide 231-232 — Indépendance des folds CV : attention danger

C’est un point qu’on pourrait facilement rater mais qui est important. On pourrait être tenté, après une CV à $K$ folds, de regarder la distribution des $K$ erreurs individuelles, calculer leur écart-type, et faire un test statistique pour comparer deux modèles.

**Problème : les $K$ folds ne sont pas indépendants.**

**Pourquoi** ? Parce que les training sets se **recouvrent largement**. Entre deux folds consécutifs d’une 3-fold CV par exemple, deux tiers des données d’entraînement sont exactement les mêmes. **Les erreurs mesurées sur des modèles entraînés sur des données très similaires sont donc corrélées.**

La variance $\mathbb{V}[\widehat{GE}_{CV}]$ est en réalité une combinaison complexe de :
- La variance moyenne due aux ensembles d’entraînement finis
- La covariance entre les erreurs de test (modèles issus de training sets qui se recouvrent)
- La covariance due au fait que des observations de test apparaissent dans d’autres training sets

Utiliser naïvement la variance empirique des $K$ folds **sous-estime** la vraie variance. Et le résultat théorique (Bengio, 2004) est déprimant : **il n’existe pas d’estimateur non biaisé** de $\mathbb{V}[\widehat{GE}_{CV}]$.

Exemple concret sur la slide : un t-test comparant LDA et SVM sur un problème de classification de spam via 20-CV donne une p-value de $7.9 \times 10^{-5}$ — ce qui semblerait très significatif. Mais ce résultat est trompeur car les hypothèses d’indépendance du t-test sont violées.

<aside>
⚠️

**Notes de cours** : Le prof dit “c’est assez déprimant, puisque la conclusion c’est qu’en fait on ne peut pas conclure grand-chose.” En pratique ça marche quand même assez bien sur la plupart des datasets de taille raisonnable, mais il faut rester prudent quand les datasets sont petits.

**En résumé, une CV pour faire la moyenne des 3 modèles donc GE intermédiaires et une GE finale c’est l’idéal PAR CONTRE, comparer deux modèles de cette même CV est faussé parce que les folds sont corrélés donc les tests sont pas fiables forcément parce que si j’ai 3 folds, et que compare 1 et 2 ou 3 y’a forcément deux qui ont utilisés les même entrainement** 

</aside>

⚠️

**Règles à retenir :**
- Par défaut → **5-CV ou 10-CV** (standard dans la plupart des cas)
- Petit dataset ($n < 200$) → **LOO ou CV répétée**
- Grand dataset → subsampling ou k-fold avec petit $k$
- Si modèle peu complexe + très petit dataset → Bootstrap 632+

- Avec $n = 100\,000$ on peut quand même avoir un problème de “petit échantillon caché” si une classe est très rare (ex : 3 malades sur 100 000 dossiers)

- Pour certains modèles, il existe des tricks pour faire du LOO efficacement (shortcut analytique) — dans ces cas LOO peut être une bonne option

## Slide 235 — Labels vs probabilités

En classification, un modèle peut produire deux types de sorties :

**Labels (hard labels)** : directement la classe prédite, encodée en one-hot. Par exemple pour 3 classes : $\hat{y} = \text{setosa} \rightarrow (1, 0, 0)$.

**Probabilités** : un vecteur $\hat{\pi}_k^{(i)} \in [0,1]^g$ pour chaque observation $i$ et chaque classe $k$, avec $\sum_k \hat{\pi}_k = 1$.

<aside>
⚠️

**Ces deux types de sorties servent de base à des métriques différentes. Comme dit le prof : si on veut juste savoir si un email est spam ou pas, le label suffit. Si on veut savoir à quel point le modèle est sûr de lui, la probabilité est indispensable.**

</aside>

---

## Slide 236 — MCE et Accuracy

**Misclassification Error (MCE)** — taux d’erreur :

$$
\rho_{MCE} = \frac{1}{m} \sum_{i=1}^{m} [y^{(i)} \neq \hat{y}^{(i)}] \in [0, 1]
$$

Si le modèle se trompe 10 fois sur 100 : $MCE = 0.10$.

**Accuracy (ACC)** — taux de bonnes prédictions :

$$
\rho_{ACC} = \frac{1}{m} \sum_{i=1}^{m} [y^{(i)} = \hat{y}^{(i)}] = 1 - MCE
$$

**Limites importantes :**
- Fragile sur les petits datasets
- Ne dit rien sur la qualité des probabilités prédites (uniquement basé sur le hard label)
- **Toutes les erreurs ont le même poids** — se tromper sur un malade cancéreux vaut la même chose que mal classer un spam. C’est souvent complètement inapproprié.

---

## Slide 237-238 — Matrice de confusion

Plutôt que de résumer tout en un seul chiffre, la **matrice de confusion met en relation les vraies classes (en colonnes) et les classes prédites (en lignes)**. La diagonale = les bonnes prédictions. **Tout ce qui est hors diagonale = les erreurs.**

Exemple sur Iris (3 classes) : les setosas sont parfaitement classées (50/50), mais 4 versicolors sont confondues avec des virginicas et inversement — la matrice le montre immédiatement d’un coup d’œil.

En **classification binaire**, on donne des noms spécifiques aux 4 cases :

|  | Vrai + | Vrai − |
| --- | --- | --- |
| Prédit + | **TP** (True Positive) | **FP** (False Positive) |
| Prédit − | **FN** (False Negative) | **TN** (True Negative) |

La classe positive est généralement la plus importante, souvent la plus rare (malade, fraudeur, défaut…). Un **FN** ici c’est un malade qu’on a renvoyé chez lui en lui disant qu’il était sain — typiquement le cas le plus grave.

> **Notes de cours** : Pour passer d’un score ou d’une probabilité à un hard label, on fixe un seuil. Ce seuil peut être ajusté selon le contexte — c’est l’analogie du “joystick de l’opératrice de radar” pendant la Seconde Guerre mondiale dont parle le prof. La sensibilité de la détection était littéralement un bouton qu’on tournait.
>

## Slides 239-240 — Classification avec coûts : exemple bancaire

L’accuracy et la matrice de confusion ne tiennent pas compte du **coût** des différentes erreurs. Or dans la vraie vie, **les erreurs n’ont pas le même poids.**

Exemple : une banque doit décider si elle accorde un prêt de 10 000€.
- Prêter à quelqu’un d’insolvable → défaut de paiement → perte de **10 000€**
- Refuser à quelqu’un de solvable → perte des intérêts → **100€** manqués

On définit une **matrice de coûts** :

$$
Costs = \frac{1}{n} \sum_{i=1}^{n} C[y^{(i)}, \hat{y}^{(i)}]
$$

|  | Solvable (vrai) | Insolvable (vrai) |
| --- | --- | --- |
| Prédit solvable | 0 | **10 000€** |
| Prédit insolvable | 100€ | 0 |

Avec la matrice de confusion concrète (70 solvables prédits solvables, 3 insolvables prédits solvables, 7 solvables prédits insolvables, 20 insolvables prédits insolvables) :

$$
Costs = \frac{1}{100}(100 \times 7 + 10000 \times 3) = 307€
$$

Si la banque donne un crédit à tout le monde sans modèle :

$$
Costs = \frac{1}{100}(10000 \times 23) = 2300€
$$

Le modèle ML fait donc économiser ~2000€ par décision en moyenne. Le prof insiste : l’accuracy peut sembler raisonnable mais masquer des coûts catastrophiques selon où se concentrent les erreurs.

> **Notes de cours** : En pratique, il est souvent très difficile d’estimer les coûts précisément. Personne ne sait vraiment combien vaut une vie humaine pour calculer le coût d’un faux négatif médical. Dans ces cas, on va évaluer avec plusieurs métriques pour avoir une vision multi-angle de la qualité du système — c’est ce qu’on appelle le **cost-sensitive learning**, qu’on ne verra pas plus en détail dans ce cours.
>

## Slide 241 — Brier Score

Le Brier Score c’est simplement le **MSE appliqué aux probabilités** — ni plus ni moins.

$$
\rho_{BS} = \frac{1}{m} \sum_{i=1}^{m} (\hat{\pi}^{(i)} - y^{(i)})^2
$$

avec $y^{(i)} \in \{0, 1\}$.

Exemple : vrai spam ($y = 1$), probabilité prédite $\hat{\pi} = 0.9$ → $BS = (0.9 - 1)^2 = 0.01$, très petit. Si la proba prédite était 0.1 pour un vrai spam → $BS = (0.1 - 1)^2 = 0.81$, grosse pénalité.

Sur le graphe :
- Courbe violette ($y = 1$) : BS faible quand $\hat{\pi}$ proche de 1 (correct), BS grand quand $\hat{\pi}$ proche de 0 (wrong)
- Courbe verte ($y = 0$) : l’inverse

Le BS **pénalise les prédictions confiantes et fausses**, mais de façon quadratique — c’est relativement doux.

![image.png](image%209.png)

---

## Slide 242 — Brier Score multiclasse

La version multiclasse compare pour **chaque classe $k$** la probabilité prédite avec le one-hot encoding :

$$
\rho_{BS,MC} = \frac{1}{m} \sum_{i=1}^{m} \sum_{k=1}^{g} (\hat{\pi}_k^{(i)} - o_k^{(i)})^2
$$

où $o_k^{(i)} = [y^{(i)} = k]$ est le label one-hot encodé.

Exemple : vrai label = chat, $o = (1, 0, 0)$, prédictions $\hat{\pi} = (0.7, 0.2, 0.1)$ :
$(0.7-1)^2 + (0.2-0)^2 + (0.1-0)^2 = 0.09 + 0.04 + 0.01 = 0.14$

Détail important : en binaire, $\rho_{BS,MC}$ est **deux fois plus grand** que $\rho_{BS}$ car on somme les carrés pour les deux classes (0 et 1), pas seulement la vraie.

## Slide 243 — Log-Loss (Cross-Entropy)

La log-loss, aussi appelée Bernoulli loss ou binomial loss, c’est la **loss utilisée pour entraîner la régression logistique**, mais elle peut aussi servir comme outer loss pour évaluer.

$$
\rho_{LL} = \frac{1}{m} \sum_{i=1}^{m} \left(-y^{(i)} \log(\hat{\pi}^{(i)}) - (1 - y^{(i)}) \log(1 - \hat{\pi}^{(i)})\right)
$$

Valeur optimale = 0. La différence fondamentale avec le Brier Score : la log-loss **pénalise de façon exponentielle** les prédictions confiantes et fausses — les courbes montent vers l’infini quand $\hat{\pi} \to 0$ pour $y=1$ ou $\hat{\pi} \to 1$ pour $y=0$.

Si je prédit 99% de probabilité que c’est la classe 1, et c’est en fait la classe 0 : pénalité colossale. Le modèle ne peut littéralement jamais dire “j’en suis sûr à 100%” sans risquer une pénalité infinie s’il a tort. Ça force le modèle à ne jamais être trop confiant quand il peut se tromper.

Version multiclasse :

$$
\rho_{LL,MC} = -\frac{1}{m} \sum_{i=1}^{m} \sum_{k=1}^{g} o_k^{(i)} \log(\hat{\pi}_k^{(i)})
$$

<aside>
⚠️

**Notes de cours** : Comparaison directe Brier Score vs Log-Loss. Si on prédit $\hat{\pi} = 0.5$ pour un exemple dont la vraie classe est 0 : BS = $(0.5)^2 = 0.25$, LL = $-\log(0.5) \approx 0.69$. Si on prédit $\hat{\pi} = 0.99$ pour un exemple de classe 0 : BS = $(0.99)^2 \approx 0.98$, LL = $-\log(0.01) \approx 4.6$. La log-loss punit donc **beaucoup** plus sévèrement la confiance mal placée.

</aside>

## Slides 244-246 — ROC Basics : le paradoxe de l’accuracy

La ROC (Receiver Operating Characteristic) est une branche de ML qui étudie l’évaluation des classifieurs binaires. Le nom vient des radars de la Seconde Guerre mondiale — les opératrices avaient littéralement un joystick pour régler la sensibilité de détection, et c’est exactement l’analogie avec le seuil de notre classifieur.

Pourquoi ne peut-on pas se contenter de l’accuracy ? L’exemple classique : si seulement 0.5% de la population a une maladie, un algorithme qui dit systématiquement “pas malade” obtient une accuracy de 99.5%. C’est le **paradoxe de l’accuracy** — très haute accuracy, système complètement inutile. Tous les malades sont renvoyés chez eux.

---

## Slides 247-248 — Coûts déséquilibrés

Le problème des classes déséquilibrées et le problème des coûts déséquilibrés sont les deux faces d’une même pièce. Même si les classes étaient équilibrées, si envoyer un malade chez lui coûte infiniment plus cher que faire faire un scanner inutile à un patient sain, l’accuracy reste une mauvaise métrique.

En pratique, estimer précisément ces coûts est très difficile. Comment chiffrer la valeur d’une vie humaine ? Comment quantifier les coûts psychologiques d’un faux positif médical ? C’est pour ça qu’on évalue souvent avec **plusieurs métriques** — pour voir la qualité du système sous différents angles sans avoir à chiffrer précisément chaque erreur.

---

## Slides 250-251 — Métriques ROC dérivées de la matrice de confusion

À partir de la matrice de confusion binaire, on dérive plusieurs métriques. Attention, chacune a souvent 2-3 noms différents selon les domaines — c’est une source de confusion classique.

**TPR — True Positive Rate** (= Recall = Sensitivity) :

$$
\rho_{TPR} = \frac{TP}{TP + FN}
$$

**→ Parmi les vrais positifs, combien a-t-on détectés ?** Sur l’exemple : $20/(20+10) = 67\%$ — on rate 33% des malades.

**TNR — True Negative Rate** (= Specificity) :

$$
\rho_{TNR} = \frac{TN}{FP + TN}
$$

**→ Parmi les vrais négatifs, combien a-t-on bien classés ?** $1820/(180+1820) = 91\%$

**PPV — Positive Predictive Value** (= Precision) :

$$
\rho_{PPV} = \frac{TP}{TP + FP}
$$

**→ Quand on dit “positif”, on a raison combien de fois ?** $20/(20+180) = 10\%$ — très peu fiable, 9 alertes sur 10 sont des faux positifs.

**NPV — Negative Predictive Value :**

$$
\rho_{NPV} = \frac{TN}{FN + TN}
$$

**→ Quand on dit “négatif”, on a raison combien de fois ?** $1820/(10+1820) \approx 99.5\%$

**Accuracy** :

$$
\rho_{ACC} = \frac{TP + TN}{TOTAL}
$$

<aside>
⚠️

**Notes de cours : La slide 252 montre un tableau complet de tous les noms alternatifs — TPR s’appelle aussi Recall, Sensitivity, probability of detection. PPV s’appelle aussi Precision. FPR (False Positive Rate) s’appelle aussi Fall-out. Il faut se méfier selon les domaines car les noms varient. Ce n’est pas critique de tous les retenir mais il faut savoir que ces synonymes existent.**

</aside>

## Slides 253-254 — F1-Score

PPV et TPR sont deux métriques contradictoires. Un classifieur très prudent qui ne dit “positif” que quand il est absolument sûr aura un bon PPV mais un TPR catastrophique (plein de malades ratés). Un classifieur très sensible qui dit “positif” pour tout le monde aura un bon TPR mais un PPV terrible (plein de fausses alertes).

Le **F1-score** est la **moyenne harmonique** de PPV et TPR :

$$
\rho_{F_1} = 2 \cdot \frac{\rho_{PPV} \cdot \rho_{TPR}}{\rho_{PPV} + \rho_{TPR}}
$$

**Propriété clé de la moyenne harmonique : elle tire vers la plus faible des deux valeurs. Si PPV = 1 et TPR = 0.2, le F1 = 0.33 — pas 0.6 comme le ferait la moyenne arithmétique. C’est voulu : un modèle qui est excellent sur une métrique mais catastrophique sur l’autre ne doit pas avoir un bon score global.**

Cas limites :
- Si TPR = 0 ou PPV = 0 → F1 = 0
- Toujours prédire négatif → Recall = 0 → F1 = 0
- Toujours prédire positif → $F1 = 2n_+/(n_+ + n)$, faible si classe positive rare

**Attention** : le F1-score ignore complètement les TN. C’est un choix — parfois approprié (détection médicale), parfois pas (si les TN comptent aussi).

## Slides 255-256 — Quelle métrique utiliser ? Il n’y a pas de réponse universelle

Le prof présente une étude comparative sur des données de credit risk (1000 observations). Quatre algorithmes : k-NN, régression logistique, random forest, CART. On les évalue sur 6 métriques différentes : TPR, TNR, PPV, F1, AUC, ACC.

Résultat : **le classement des modèles change selon la métrique**. Ce qui est premier en TPR n’est pas premier en TNR ni en PPV. Il n’y a pas de modèle universellement meilleur.

Deux exemples concrets du prof pour illustrer que le choix dépend du contexte métier :

**Crédit bancaire** : les défauts sont graves mais la banque doit prendre des risques pour être rentable. Une mesure équilibrée comme le F1-score est souvent appropriée.

**Détection d’armes à l’aéroport** : un faux négatif (une arme non détectée) est inacceptable. On maximise le TPR même si ça génère des fausses alertes — on préfère arrêter des passagers innocents plutôt que de rater une arme.

**Le message final du prof : afficher plusieurs métriques en même temps est souvent la meilleure pratique. Ça donne une vision complète et permet à chacun de choisir selon ses priorités. Un algorithme qui est souvent dans le top des métriques offre le meilleur compromis général — mais aucun n’est parfait sur tout.**

## Slide 258 — L’espace ROC

Pour comparer des classifieurs, on les représente par leur TPR et FPR et on les positionne dans un espace à deux axes. On peut aussi utiliser d’autres paires de métriques en tension — par exemple TPR et PPV (Precision-Recall). Dans l’espace ROC classique :

$$
TPR = \frac{TP}{TP + FN} \quad FPR = \frac{FP}{FP + TN}
$$

Quand on compare C1, C2 et C3 dans cet espace, C1 peut **dominer** C3 (meilleur sur les deux métriques simultanément — win-win, aucune raison de choisir C3). Mais la comparaison entre C1 et C2 peut être moins claire : C2 détecte plus de positifs (TPR plus haut) mais au prix de plus de faux positifs (FPR plus haut). C’est un **compromis** qui dépend du contexte.

## Slide 259 — Meilleur et pire classifieur dans l’espace ROC

Le **meilleur classifieur possible** est dans le **coin supérieur gauche** : TPR = 1 et FPR = 0. Il détecte tous les positifs sans aucun faux positif.

La **diagonale** représente le classifieur aléatoire : si on classe 25% des éléments comme positifs au hasard, on obtient TPR = 0.25 et FPR = 0.25 — les deux bougent proportionnellement. Être sur la diagonale revient à jouer à pile ou face, c’est le comportement d’un classifieur complètement non discriminant.

---

## Slide 260 — Pourquoi un classifieur ne devrait jamais être sous la diagonale

Un modèle sous la diagonale est paradoxalement récupérable. Si on **inverse les prédictions** ($0 \leftrightarrow 1$), le point se reflète symétriquement par rapport à la diagonale :

$$
TPR_{new} = 1 - TPR \quad FPR_{new} = 1 - FPR
$$

Et il devient meilleur que le hasard. Ce qui veut dire que si un classifieur est sous la diagonale, ce n’est pas qu’il est mauvais au sens où il ne trouve rien — c’est qu’il a trouvé une corrélation mais l’interprète à l’envers. **En pratique**, on espère ne jamais tomber là, sinon c’est un signe que quelque chose cloche dans le processus d’apprentissage.

<aside>
⚠️

**Notes de cours : En pratique le pire qu’on puisse avoir c’est un modèle aléatoire (sur la diagonale), pas un modèle sous la diagonale — parce qu’un modèle sous la diagonale on peut toujours l’inverser pour qu’il soit meilleur que le hasard.**

</aside>

## Slide 261 — Invariance de TPR et FPR aux proportions de classes

TPR et FPR sont **insensibles** à la distribution des classes dans le test set au moment de la prédiction — c’est-à-dire qu’ils ne changent pas si on modifie le ratio $n_+/n_-$.

Exemple concret : avec $n_+/n_- = 1$ → TPR = 0.8, FPR = 0.5. Avec $n_+/n_- = 2$ (deux fois plus de positifs) → TPR = 0.8, FPR = 0.5. Identiques. Par contre le MCE change : on passe de 0.35 à 0.30 parce qu’il dépend du total.

**Attention** — cette invariance ne tient que **pour l’évaluation**. Si les proportions de classes changent pendant **l’entraînement**, les probabilités postérieures estimées par le modèle peuvent changer. Un modèle entraîné sur des données à 90% de positifs va biaiser ses prédictions vers la classe positive.

## Slides 262-269 — Construction pas à pas de la courbe ROC

La courbe ROC représente tous les seuils de décision possibles en un seul graphique. Pour la construire :

**Algorithme :**
1. Trier toutes les observations par score **décroissant**
2. Partir du point $(0, 0)$ avec le seuil $c = 1$ — tout est classé négatif
3. Pour chaque observation suivante :
- Si c’est un **positif** → monter de $1/n_+$ sur l’axe TPR (un vrai positif de plus)
- Si c’est un **négatif** → avancer de $1/n_-$ sur l’axe FPR (un faux positif de plus)

La courbe obtenue est une **suite d’escaliers** qui part de $(0,0)$ et arrive à $(1,1)$.

Exemple pas à pas avec 6 positifs et 6 négatifs (triés par score décroissant) :

| Seuil $c$ | TPR | FPR | Ce qui s’est passé |
| --- | --- | --- | --- |
| 0.9 (après obs. 1 pos) | 0.167 | 0 | Première positif, monte |
| 0.85 (après obs. 2 pos) | 0.333 | 0 | Deuxième positif, monte |
| 0.66 (après obs. 3 pos) | 0.5 | 0 | Troisième positif, monte |
| 0.6 (après obs. 4 nég) | 0.5 | 0.167 | Premier négatif, droite |
| 0.55 (après obs. 5 pos) | 0.667 | 0.167 | Quatrième positif, monte |
| 0.3 (plusieurs) | 0.833 | 0.5 | Plusieurs négatifs |
| 0 | 1 | 1 | Tout classé positif |

Lecture intuitive : une montée verticale = gain de vrais positifs sans coût en faux positifs — c’est bien. Un mouvement horizontal = on ajoute des faux positifs sans gain en détection — c’est le coût.

<aside>
⚠️

**Notes de cours** : Le seuil $c$ choisi entre deux observations consécutives n’a pas d’importance — n’importe quelle valeur entre leurs deux scores donnera le même résultat de classification. C’est pour ça que sur les slides, le prof choisit $c = 0.66$ entre les observations de score 0.69 et 0.65.

</aside>

## Slide 270 — Propriétés de la courbe ROC et choix du seuil

**Plus la courbe tire vers le coin supérieur gauche, meilleur est le classifieur. Si deux courbes se croisent, un modèle peut être meilleur dans certaines régions de FPR — le choix dépend alors de ce qui est le plus important dans l’application.**

**Effet du seuil :**
- Seuil bas → on prédit positive très libéralement → TPR et FPR élevés (partie droite de la courbe)
- Seuil haut → on prédit positive seulement si très sûr → TPR et FPR faibles (partie gauche)

Sans information sur les coûts, **il n’existe pas de meilleur seuil universel**. La courbe ROC permet de visualiser tous les compromis possibles.

---

## Slide 271 — Choisir le point d’opération (Operating Point)

En pratique le choix du seuil est souvent fait **visuellement et a posteriori** selon le contexte. La démarche :
1. Identifier les points **non dominés** sur la courbe (aucun autre point n’est simultanément meilleur sur TPR et FPR)
2. Évaluer les compromis TPR/FPR disponibles
3. Décider selon les contraintes métier (coûts, prévalence)
4. Choisir le seuil correspondant à ce point

<aside>
⚠️

**Notes de cours** : C’est l’analogie du joystick de l’opératrice de radar — elle ajustait physiquement la sensibilité de détection. Notre seuil $c$ joue le même rôle. Certains points sur la courbe peuvent avoir le même TPR mais un FPR différent : dans ce cas on choisit celui avec le moins de faux positifs. C’est le concept de **dominance**.

</aside>

## Slide 272 — AUC : Area Under the ROC Curve

L’**AUC** (Area Under the Curve) résume la performance d’un classifieur en une seule valeur $\in [0,1]$, indépendante du seuil choisi.

- AUC = 1 → classifieur parfait (courbe qui monte à (0,1) puis va à (1,1))
- AUC = 0.5 → classifieur aléatoire (diagonal)
- AUC = 0 → classifieur parfait avec labels inversés (peut être corrigé en inversant)

C’est la métrique de choix pour comparer des modèles sans avoir à fixer un seuil — utile dans les pipelines automatiques ou le tuning d’hyperparamètres.

---

## Slide 273 — AUC comme métrique basée sur les rangs

L’AUC a une interprétation probabiliste fondamentale : c’est la **probabilité que le classifieur attribue un score plus élevé à un exemple positif tiré au hasard qu’à un exemple négatif tiré au hasard** :

$$
AUC = P(s(x^+) > s(x^-))
$$

Pour le vérifier empiriquement : on tire 3000 fois une paire (positif aléatoire, négatif aléatoire), on regarde combien de fois le positif a un score plus grand. La proportion converge vers l’AUC — dans l’exemple du cours, elle converge vers 0.9167.

C’est un résultat démontré — il est **toujours vrai**, sans conditions particulières. Ça en fait une métrique de **ranking** : l’AUC mesure la qualité de l’ordonnancement des scores, pas les valeurs exactes. Un classifieur parfait range toujours tous les positifs au-dessus de tous les négatifs.

---

## Slides 274-276 — Partial AUC

L’AUC globale intègre sur **toute** la courbe ROC, mais dans certains contextes on ne s’intéresse qu’à une **région précise**. En biomédical par exemple, on veut un TPR élevé (détecter la maladie) mais on doit contraindre le FPR (éviter les traitements inutiles). Des parties de la courbe où FPR > 0.2 peuvent être inacceptables — inutile d’évaluer sur ces zones.

Le **partial AUC (pAUC)** calcule l’aire uniquement dans la région d’intérêt, définie par un FPR maximal toléré et/ou un TPR minimal requis. On peut contraindre sur l’un ou les deux axes.

Comme la valeur brute du pAUC dépend des bornes choisies, on le **normalise** pour le rendre comparable entre configurations :

$$
pAUC_{corrected} = \frac{1}{2}\left(1 + \frac{pAUC - pAUC_{min}}{pAUC_{max} - pAUC_{min}}\right)
$$

La correction ramène la mesure dans $[0.5, 1]$ où 0.5 = classifieur aléatoire dans cette zone et 1 = classifieur optimal. Le **2-way pAUC** peut contraindre simultanément les deux axes : par exemple “TPR > 0.5 ET FPR < 0.3”.

## Slides 279-283 — AUC Multi-Classe

La courbe ROC est naturellement définie pour la classification binaire. Pour l’étendre à $g \geq 3$ classes, il faut ruser.

**Définition de $AUC(k \mid \ell)$** : pour une paire de classes $k$ (positive) et $\ell$ (négative), on filtre le dataset aux observations de ces deux classes uniquement, et on calcule l’AUC standard en utilisant le score $\hat{\pi}_k$ comme discriminant. $AUC(k \mid \ell)$ = probabilité qu’un membre de la classe $k$ reçoive un $\hat{\pi}_k$ plus élevé qu’un membre de la classe $\ell$.

**Asymétrie importante** : en binaire, $AUC(1|0) = AUC(0|1)$ toujours. En multi-classe, $AUC(k|\ell) \neq AUC(\ell|k)$ en général. Pourquoi ? En binaire, si $\hat{\pi}_1$ classe bien, $\hat{\pi}_0 = 1 - \hat{\pi}_1$ classe aussi bien dans l’autre sens. En multi-classe, il y a une troisième classe possible — les probabilités de $\hat{\pi}_k$ et $\hat{\pi}_\ell$ peuvent évoluer différemment selon la présence de la troisième classe.

**Approche 1-vs-1 (Hand & Till, 2001)** : calculer $AUC(k|\ell)$ pour toutes les paires, puis faire la moyenne :

$$
AUC_{MC} = \frac{1}{g(g-1)} \sum_{k \neq \ell} AUC(k|\ell) \in [0, 1]
$$

**Approche 1-vs-rest** : pour chaque classe $k$, la traiter comme positive et toutes les autres comme négatives, puis faire la moyenne des $g$ AUC. Attention : cette approche crée un déséquilibre artificiel de classes même si les classes originales sont équilibrées. Si les classes sont initialement équilibrées (ex : 50 fleurs de chaque dans Iris), en 1-vs-rest on a 50 positifs contre 100 négatifs. On peut pondérer les AUC individuels par les priors des classes pour corriger ça (Ferri et al., 2003).

> **Notes de cours** : Le prof insiste — l’asymétrie en multi-classe vient du fait qu’on utilise la probabilité de la classe $k$ comme score, pas celle de $\ell$. En binaire, connaître l’un détermine l’autre (car $\hat{\pi}_0 + \hat{\pi}_1 = 1$). En multi-classe, on a une troisième classe qui “absorbe” une partie de la probabilité et rompt cette réciprocité.
>

## Slides 284-289 — Courbes Precision-Recall

La courbe **Precision-Recall (PR)** est une variante de la courbe ROC qui trace la Precision (PPV) en fonction du Recall (TPR) pour tous les seuils possibles. C’est exactement la même procédure de construction que la ROC, mais avec des axes différents.

$$
Precision = \rho_{PPV} = \frac{TP}{TP + FP} \qquad Recall = \rho_{TPR} = \frac{TP}{TP + FN}
$$

**Le coin idéal est en haut à droite (Precision = 1 et Recall = 1). Ni la Precision ni le Recall ne dépendent des TN — c’est la grande différence avec la ROC où le FPR utilise les TN.**

**Pourquoi c’est meilleur avec des classes déséquilibrées ?** Parce que le FPR est insensible aux changements de la classe négative (car TN est énorme, un changement même important de FP donne un changement infime de FPR). Exemple numérique : avec $n_- = 10000$ positifs, passer de FP=10 à FP=100 :
- FPR : $0.001 \to 0.01$ — imperceptible sur la courbe ROC
- PPV : $10/11 \approx 91\% \to 100/200 = 50\%$ — effondrement visible sur la PR curve

Avec $\pi = 0.003$ (classe très rare) vs $\pi = 0.5$ (équilibré) : les courbes ROC sont quasi identiques alors que les courbes PR changent drastiquement. La ROC donne une fausse impression que le classifieur s’en sort bien.

**Résultat théorique important** : si une courbe domine l’autre dans l’espace ROC (elle est entièrement au-dessus), elle domine aussi dans l’espace PR, et réciproquement. Les deux diagrammes sont d’accord quand il y a une dominance stricte. Les différences apparaissent quand les courbes se croisent ou quand les classes sont très déséquilibrées.

**Pratique recommandée** :
- Classes déséquilibrées → **préférer la PR curve**
- Pour comparer peu de modèles → **tracer les deux**, observer et réfléchir
- Pour le tuning automatique → utiliser le **PR-AUC** (ou une version partielle)
